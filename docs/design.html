shiver: design

Inner-voice popups for the desktop.

Goal Architecture Pack format Notifications Overlay Licensing

Goal

A small tool that interjects on the desktop: a short line, attributed to a named “voice”, shown as a popup with an optional sound. It started as a way to get Disco Elysium-style skill interjections (Volition telling you to go to bed, Shivers saying something about the city), but everything is data-driven, so users can bring their own voices, text and sounds.

Architecture

Triggers

  • manual CLI
  • systemd timer
  • shell hooks
  • daemon (later)
→

shiver-core

  • load packs
  • pick a line (random / weighted / by voice / by tag)
  • resolve sound + icon
→

Outputs (crates/shiver)

  • stdout (cowsay-style)
  • notify (freedesktop D-Bus)
  • sound (pw-play / paplay)
  • overlay (later, layer-shell)
  • Core picks a line and resolves its voice, sound and icon. It has no side effects, so it can be reused by other front-ends.
  • Outputs each present that result in one way (terminal, notification, sound). Sound is a separate output so any visual output can be combined with it.
  • Triggers are outside the core. The CLI is the shared entry point that timers, shell hooks, other programs and a future daemon all call.

Pack format

A pack is a directory: ~/.config/shiver/packs/<pack-name>/pack.toml plus assets referenced by relative paths.

Voices from all packs are merged by name, so one pack can add lines for voices defined in another. If two packs define the same voice, shiver warns and keeps the first.

[pack]
name = "example"
license = "CC0-1.0"

[voices.resolve]
display = "RESOLVE"
color = "#8a5cd6"
sound = "sounds/resolve.ogg"   # default for this voice; optional
icon = "icons/resolve.png"     # optional

[[lines]]
voice = "resolve"
text = "You've been staring at this bug for an hour. Stand up."
tags = ["late", "idle"]
weight = 1.0                   # optional, default 1.0
# sound = "sounds/other.ogg"   # optional per-line override

Notifications on Linux

  • notify-rust speaks the freedesktop notification spec over D-Bus (zbus). It works on COSMIC, KDE and GNOME. Styling belongs to the desktop, so we can only set the summary (voice name), body, icon, urgency and timeout.
  • Body markup support varies by server, so the body is plain text.
  • The spec has a sound-file hint, but servers often ignore it, so play sound ourselves.

Overlay (v2) notes

  • On Wayland a normal window can't position itself or stay on top. Use the wlr-layer-shell protocol, which COSMIC and KDE support and GNOME doesn't.
  • Candidates:
    • libcosmic (iced-based, MPL-2.0): native look on COSMIC and layer-shell support built in. A heavier dependency.
    • GTK4 with gtk4-layer-shell: mature, but needs a C library at build/run time.
    • Raw smithay-client-toolkit with a small renderer: the lightest option and the most work.
  • Put the overlay in its own crate or behind a cargo feature so the plain CLI stays lightweight.
