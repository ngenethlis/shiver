0004: Default pack and shiver init

Created 2026-11-18 · done

Problem

After installing, there are no packs, so shiver say and shiver notify just fail with “no packs found”. New users have to write a pack before seeing anything, and have no example to start from.

Proposal

Ship an original default pack and a command that installs it:

$ shiver init
created ~/.config/shiver/packs/default/pack.toml
try `shiver say` or `shiver notify`; edit the pack to make it yours
  • The pack is compiled into the binary, so init works without the source code. It's written as a normal pack folder that users can edit.
  • init won't overwrite an existing default pack unless given --force.
  • When say or notify find no packs, the error suggests running shiver init.

The pack

Five original voices about life at a computer, about 30 lines in all, tagged so --tag is useful. Sounds point at the desktop's standard system sounds. Released as CC0.

Decisions

ChoiceWhy
init writes the pack to disk instead of using it silently from the binary. The pack becomes the user's to edit, and it's visible in shiver list like any other.
Sounds are the freedesktop system sounds, by absolute path. Installed on most Linux desktops (sound-theme-freedesktop). Where they're missing, shiver warns and stays silent.
The pack lives in the repo at crates/shiver/packs/default/ with its licence stated there. Must be inside the crate to be compiled in; the licence note follows the content rule in AGENTS.md.
Without --force, an existing pack is never overwritten. Users may have edited it.

Done when

  • shiver init creates the pack, refuses to overwrite it, and --force replaces it; all tested.
  • The pack loads with no warnings where system sounds are installed, and every voice has lines.
  • CI checks pass.
