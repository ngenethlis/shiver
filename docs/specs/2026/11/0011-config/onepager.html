0011: Config file

Created 2026-11-18 · done

Problem

Several earlier specs fixed a value and said “configurable later”: the time windows for morning and late, the history size, the hook's ignore list. Some things can't be changed at all today, like turning sound or a pack off, or the volume.

Proposal

An optional ~/.config/shiver/config.toml. Every setting has a default, so an empty or missing file changes nothing.

packs_dir = "~/shiver-packs"        # where packs live
disabled_packs = ["work"]             # pack folders to skip

[sound]
enabled = true
volume = 0.6                          # 0.0 to 1.0

[notify]
default_icon = true                   # Signal Flame for voices without an icon

[cooldowns]
enabled = true
history = 50                          # picks remembered

[context]
morning = "06:00-10:30"
late = "23:00-04:00"
boost = 3.0

[hook]
min_gap = "10m"
ignore_commands = ["make"]            # added to the built-in list
  • shiver config prints where the file is and every setting in effect, as TOML you can copy into the file.
  • Flags and environment variables still win: --packs-dir and SHIVER_PACKS_DIR beat packs_dir, and --min-gap beats hook.min_gap.
  • A mistake in the file (bad syntax, an unknown key, a bad value) is an error naming the line, not silently ignored, so typos get noticed.

Scope

InOut (later)
  • The settings above
  • shiver config
  • --config FILE and SHIVER_CONFIG
  • Timer schedule in the file (it lives in the timer unit)
  • Per-voice settings
  • Reloading while running (no daemon yet)

Decisions

ChoiceWhy
Unknown keys are errors. A misspelt setting that's silently ignored is worse than a clear message.
disabled_packs rather than a list of enabled packs. New packs work as soon as they're dropped in; you only list exceptions.
ignore_commands adds to the built-in list. Nobody has to copy the defaults to add one command.
Volume is passed to pw-play --volume / paplay --volume. Both players support it; no audio code in shiver.

Done when

  • Tests cover parsing, defaults, errors, precedence, and each setting's effect.
  • All CI checks pass.
