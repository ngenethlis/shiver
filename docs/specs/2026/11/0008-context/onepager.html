0008: Time-of-day context

Created 2026-11-18 · done

Problem

Lines tagged late (“Past midnight, every idea feels brilliant…”) can show up at 10 in the morning, and morning lines at night. Tags only matter when you pass --tag yourself, so the timer's random popups ignore the time completely.

Proposal

Two tags become context tags, tied to the local time:

TagActive
morning05:00–11:00
late22:00–05:00
  • Only in their time: a line with a context tag is only picked while one of its context tags is active. Lines without context tags can be picked any time.
  • More likely in their time: while a context is active, its lines are 3× as likely, so the time of day is noticeable.
  • Asking overrides it: --tag late at noon still gives late lines.
  • Previewing: --at 23:30 on say or notify pretends it's that time.

Pack authors don't need to change anything: tags they already use for morning and late start working on their own.

Scope

InOut (later)
  • morning and late from local time
  • Restrict and boost when picking
  • --at HH:MM
  • Changing the time windows or the boost (config file, 0010)
  • idle (needs desktop-specific idle detection; backlog)
  • Weekday or weekend tags

Decisions

ChoiceWhy
Context tags restrict as well as boost. A “past midnight” line at noon is wrong, not just unlikely.
The time logic lives in shiver-core, given the time as a number; the binary reads the clock. Keeps the core free of system access and makes it easy to test.
Local time via the jiff crate. The standard library can't read the local time zone. jiff is pure Rust, well maintained, and MIT-licensed.
If the local time can't be read, no context tag is active (with a warning). Context-tagged lines then only appear with --tag; nothing breaks.

Done when

  • Tests cover the windows (including across midnight), restriction, boost, explicit --tag and --at.
  • All CI checks pass.
