0006: Random popups with a systemd timer

Created 2026-11-18 · in-progress

Problem

shiver only speaks when asked. The point is for voices to interject on their own through the day, and v0 planned a systemd user timer for that instead of a daemon. Today users would have to write the timer themselves.

Proposal

Two ways to set it up, both producing the same timer:

  • shiver timer enable writes the service and timer to ~/.config/systemd/user/, using the exact path of the running shiver binary, and starts the timer. shiver timer disable stops it and removes the files. shiver timer status shows when the next popup is due.
  • Example files in contrib/systemd/, with README steps, for people who prefer to manage units themselves. They assume the binary is at ~/.cargo/bin/shiver.

Schedule

By default, a popup roughly every 45 minutes between 9:00 and 21:00: 16 slots (9:00, 9:45, 10:30, … 20:15), each fired at a random point up to 20 minutes after the slot, so they don't feel mechanical. Nothing at night, and missed slots (computer asleep) are skipped, not caught up.

Three options change it:

OptionDefaultWhat it does
--every45mTime between slots, e.g. 30m, 1h, 1h30m.
--between09:00-21:00Daily window the slots fall in. 00:00-24:00 for all day; 22:00-02:00 crosses midnight.
--jitter20mEach popup comes at a random point up to this long after its slot. 0m for exact times.

Running enable again with other options replaces the schedule. enable and status show when popups can really arrive. Because of the jitter, that can be a little after the window's end; if it is, enable warns and suggests a smaller jitter or an earlier end.

$ shiver timer enable --every 1h --between 10:00-18:00
wrote ~/.config/systemd/user/shiver.service
wrote ~/.config/systemd/user/shiver.timer
schedule: every 1h between 10:00-18:00, jitter 20m (popups 10:00-17:20)
timer enabled; next popup: Wed 2026-11-18 11:07

Scope

InOut
  • shiver timer enable | disable | status
  • contrib/systemd/shiver.service and .timer
  • README section
  • Per-weekday schedules
  • Shell hooks and context-aware picks (v1)
  • A daemon (v2)
  • Non-systemd systems

Decisions

ChoiceWhy
Fixed slots plus a random delay, not “every 45 minutes since the last one”. systemd can limit calendar slots to daytime hours; an interval timer can't. shiver turns the options into the slot list.
Jitter must be shorter than the interval. Otherwise popups could bunch up or come out of order.
Popups running past the window's end give a warning, not an error. It may be what you want; the warning makes sure you know.
enable writes the binary's real path. Works wherever shiver is installed; no path editing.
A custom packs folder given to enable (--packs-dir or SHIVER_PACKS_DIR) is written into the service. The timer then uses the same packs you tested with.
enable refuses to overwrite unit files it didn't write, unless --force. Protects hand-edited timers.
A test checks the example files match what enable writes. The two options can't drift apart.

Done when

  • Tests cover the schedule options and their errors, the unit files, enable, disable and status (with a fake systemctl).
  • You've run shiver timer enable on COSMIC, seen a popup arrive on its own, and disable removed it.
  • CI checks pass.
