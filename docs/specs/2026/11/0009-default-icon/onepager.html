0009: Default notification icon

Created 2026-11-18 · in-progress

Problem

Voices without their own icon, which includes every voice in the default pack, show notifications with no icon or a generic one. shiver now has a logo, the Signal Flame, and notifications should carry it.

Proposal

  • The 128×128 Signal Flame icon from assets/logo/ is compiled into the binary.
  • The first time a notification needs it, shiver writes it to ~/.local/share/shiver/icons/shiver.png (and rewrites it if a newer shiver ships a different icon).
  • Any notification whose voice has no icon uses it, including one-off --text messages. Voices with their own icon keep it.

Scope

InOut
  • Embedding and installing the icon
  • Using it as the fallback notification icon
  • Turning the default icon off (config file)
  • Installing into the desktop's icon theme or a .desktop file
  • Publishing to crates.io (the icon lives outside the crate; see backlog)

Decisions

ChoiceWhy
Compiled in, written out on demand. Notification servers need a file path or a themed icon name; this works for cargo install with no extra setup step.
128×128. Notifications show icons at 48–64 px, so 128 covers HiDPI and adds only ~12 KB to the binary.
If writing the icon fails, warn and show the notification without it. An icon is never worth a failed popup.

Done when

  • Tests cover installing, reusing and updating the icon file, and the fallback.
  • You see the Signal Flame on a shiver notify on COSMIC.
  • All CI checks pass.
