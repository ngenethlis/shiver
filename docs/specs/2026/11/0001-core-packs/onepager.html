0001: Core packs and line selection

Created 2026-11-18 · done

Problem

shiver has no code yet. Every command (say, notify, list) needs the same foundation: read the user's packs, know which voices exist, and pick a line to show. That logic belongs in shiver-core so the CLI, and anything built later, share it.

Proposal

Set up the Cargo workspace and build shiver-core with two jobs:

  • Load a library of packs from a folder the caller passes in. Each subfolder with a pack.toml is a pack. Voices from all packs go into one shared pool, so a pack can add lines for voices defined elsewhere.
  • Pick a line at random, optionally only from one voice or one tag. Lines with a higher weight are picked more often. The result carries the line's text, its voice (name and colour), and the sound and icon to use.

Loading is forgiving: a broken pack or line is skipped and reported as a warning, and everything else still loads, so one mistake never stops popups. The core doesn't print anything; it hands warnings back to the caller.

Scope

InOut (later specs)
  • Cargo workspace with the shiver-core crate
  • pack.toml parsing and validation
  • Loading every pack in a folder, merging voices
  • Resolving sound and icon paths
  • Weighted random pick, filtered by voice and tag
  • Pack summaries for shiver list
  • The shiver binary and its commands
  • Finding ~/.config/shiver/packs
  • Notifications and sound playback
  • Cooldowns and context-aware selection
  • A config file

Decisions

ChoiceWhy
Voices are shared across packs; if two packs define the same voice, the first wins. Lets a pack add lines without redefining voices. Packs load in folder-name order, so “first” is predictable.
A malformed pack.toml skips that pack with a warning. One broken pack shouldn't stop the others.
A line with an unknown voice is skipped with a warning. Same reason, at line level.
A missing sound or icon file is dropped with a warning. The line still shows, just without that sound or icon.
Weights are optional (default 1) and must be greater than 0. Lets authors make lines rarer or more common. Invalid weights skip the line with a warning.
A missing packs folder means an empty library, not an error. A fresh install has no packs yet; the CLI can say so.
The core takes the packs folder as an argument. Keeps the core free of desktop and config-path logic, and easy to test.

Done when

  • The workspace builds and fmt, clippy and tests are clean.
  • Tests cover parsing, every skip-with-warning case, voice merging, path resolution, filtering, and that weights change how often lines are picked.
  • The test packs are original content.
