0002: The shiver command

Created 2026-11-18 · done

Problem

shiver-core can load packs and pick a line, but there's no way to use it yet. v0 needs a command that prints a line in the terminal, shows it as a desktop notification with a sound, and lists what's installed.

Proposal

Add the shiver binary with three commands:

  • shiver say prints a random line in a speech box, with the voice name in the voice's colour when the terminal supports it. 
     RESOLVE
╭──────────────────────────────────────╮
│ You've been staring at this bug for  │
│ an hour. Stand up.                   │
╰──────────────────────────────────────╯
  • shiver notify shows a random line as a desktop notification (voice name as the title, the line as the body, the voice's icon) and plays its sound. --no-sound skips the sound. --text "..." with --voice sends a one-off message instead of a random line.
  • shiver list shows each pack with its folder, voices and number of lines.

say and notify both take --voice and --tag to narrow the pick. Packs come from ~/.config/shiver/packs; --packs-dir or SHIVER_PACKS_DIR point elsewhere. Pack warnings are printed to the error output on every run, so problems get noticed.

Each way of showing a line (terminal, notification, sound) is its own small module, so the overlay planned for v2 can be added beside them.

Scope

InOut (later specs)
  • say, notify, list
  • Finding the packs folder
  • Speech box with wrapping and colour
  • Notifications over D-Bus
  • Sound via pw-play, falling back to paplay
  • systemd timer for random popups
  • An example pack in the repo
  • Shell hooks and context-aware picks
  • Cooldowns, config file, overlay

Decisions

ChoiceWhy
say prints a speech box; text wraps at 60 columns. Readable in any terminal size, and the box stays compact.
Colour only when printing to a terminal and NO_COLOR isn't set. Piped output stays clean; respects the common NO_COLOR convention.
One-off --text with an unknown voice uses that name as is. Scripts can send a message without making a pack.
Sound plays in the background and shiver doesn't wait for it. The notification is never delayed by audio.
No sound player found, or the sound file is missing: a warning, but the notification still shows. Sound is a bonus; it shouldn't break the popup.
No packs or no matching line: say and notify fail with a clear message; list just says there are none. A timer or script can see that nothing was shown.
Notifications use plain text and the desktop's default timeout. Markup and timeouts vary between desktops.

Done when

  • Automated tests cover say, list, the packs-folder options, warnings, error messages, the speech box and the sound fallback.
  • You've run shiver notify on COSMIC and seen the notification and heard the sound (notifications can't be tested automatically).
  • fmt, clippy and tests are clean.
