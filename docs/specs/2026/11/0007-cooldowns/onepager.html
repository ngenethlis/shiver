0007: Cooldowns

Created 2026-11-18 · done

Problem

Every pick is independent, so with the timer running all day the same line can come back within minutes, and one voice can speak several times in a row. It makes the voices feel like a random generator instead of characters.

Proposal

shiver remembers its recent picks and steers away from them:

  • No repeated lines: a line isn't shown again until every other matching line has had a turn, as far as the history reaches (the last 50 picks). With the 30-line default pack, a line can't repeat within 30 popups.
  • When everything has been seen: for example --tag win with only five matching lines, shiver picks among the half that was shown longest ago, so it still never repeats the latest ones.
  • Voices take turns: the same voice doesn't speak twice in a row if another voice has a line available. Asking for a voice with --voice turns this off.
  • Weights still apply within whatever is left.

The history is a small text file in ~/.local/state/shiver/history, written by say and notify (not by one-off --text messages). Deleting it resets everything.

Scope

InOut (later)
  • History file: read, append, keep the last 50
  • Line and voice cooldowns in the core
  • say and notify use them
  • Configuring the history size or turning cooldowns off (config file, 0010)
  • Time-based cooldowns (“not within 2 hours”)
  • A command to show or clear the history

Decisions

ChoiceWhy
Count-based (recent picks), not time-based. Works the same whether you call say ten times a minute or the timer fires hourly.
Lines are identified by a hash of voice and text. Editing or reordering other lines doesn't reset the history; editing a line's own text makes it fresh.
The cooldown logic lives in shiver-core; the file lives in the binary. The core stays pure and testable; only the binary touches the state folder.
An unreadable or corrupt history is ignored with a warning, never an error. Losing the history only means a repeat might happen.

Done when

  • Tests show: no repeats until all lines are used, fallback to the oldest half, voices alternate, --voice disables the voice rule, and the history file is written, trimmed to 50 and survives corruption.
  • All CI checks pass.
