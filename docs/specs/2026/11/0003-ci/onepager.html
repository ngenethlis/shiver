0003: Continuous integration

Created 2026-11-18 · in-progress

Problem

The rules in AGENTS.md (formatting, clippy, tests, the spec layout) are only checked when someone remembers to run them. A push or pull request can break them without anyone noticing.

Proposal

A GitHub Actions workflow that runs on every push to main and every pull request, with seven checks shown separately on GitHub:

  • Format: cargo fmt --check
  • Lint: cargo clippy --all-targets -- -D warnings
  • Test: cargo test
  • Coverage: cargo llvm-cov measures how much code the tests run. The result shows on the GitHub run page, and the check fails if coverage drops below today's level.
  • Dependencies: cargo deny check fails if a dependency has a license that doesn't fit MIT OR Apache-2.0, or a known security problem.
  • Docs: cargo doc with warnings as errors, so broken doc links are caught.
  • Specs: cargo xtask check-specs, a small Rust tool in the repo that checks every spec folder follows the format in AGENTS.md.

The spec checker runs the same way locally, so you and agents can check specs before pushing.

What the spec checker checks

  • Folders are docs/specs/<yyyy>/<mm>/<id>-<name>/, with a 4-digit id and a kebab-case name. Ids are unique.
  • spec.md starts with id, name, status and created, and they match the folder (same id, name, year and month).
  • Status is one of draft, approved, in-progress, done, and the one-pager shows the same status.
  • onepager.html exists and links the shared stylesheet.
  • tasks.md exists once work has started (in-progress or done).
  • Each requirement (### R1: ...) has acceptance criteria.
  • A done spec has no unticked boxes in spec.md or tasks.md.

Scope

InOut
  • The workflow file
  • The xtask spec checker, with tests
  • Mentioning cargo xtask check-specs in AGENTS.md
  • Release builds or publishing to crates.io
  • Codecov or other hosted coverage, spell-checking
  • Checking that named tests in specs actually exist
  • Branch protection settings (done on GitHub by you)
  • Other operating systems

Decisions

ChoiceWhy
Spec checker written in Rust as an xtask, not a shell or Python script. Same language and tooling as the project, unit-testable, and runs with nothing extra installed.
Seven separate jobs. On GitHub you see at a glance which kind of check failed.
Coverage minimum = today's coverage, rounded down. Coverage can only go up. No hosted service (Codecov) for now: no account or token needed.
Linux only, stable Rust. shiver targets Linux desktops.
Actions pinned to exact versions, with build caching. Repeatable runs and faster builds.

Done when

  • The spec checker passes on specs 0001–0003 and its tests cover each rule.
  • Coverage, dependency and doc checks pass locally.
  • A push to GitHub shows the seven checks passing, with coverage on the run page.
